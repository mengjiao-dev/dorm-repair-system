# 宿舍报修管理系统

基于 Spring Boot 的本地课程项目，包含可执行程序、完整源码、自动化测试和部署配置。四种角色共享同一数据库，页面操作真实调用后端接口。

## 立即运行

1. 将压缩包**完整解压**，不要在压缩包内部运行。
2. 确认电脑有 Java 17 或更高版本。本机已检测到 Java 17。
3. 双击项目根目录的 `start.cmd`，保留启动窗口。
4. 等待出现 `Started Application`，在浏览器访问 **http://localhost:18080**。
5. 登录演示账号，开始操作。停止系统时在启动窗口按 Ctrl+C。

如果启动窗口很快退出，请查看最后几行错误。端口占用时可自行运行 `java -jar dorm-repair.jar --server.port=18082`，然后访问对应端口。

## 可以做什么

- 学生：提交报修、查询与筛选、上传图片、取消未派单申请、验收评分、申请返修、查看通知。
- 宿管：在授权楼栋审核、拒绝、派单、接单前转派，按工种查看维修人员与待办数量。
- 维修人员：查看受派任务、接单、上传现场图片、填写维修结果。
- 管理员：新建与启停账号、增加与启停报修类别、查看通知事件与重试失败事件。
- 共同能力：工单时间线、状态统计、类别统计、历史日志与图片访问权限。

## 两种运行方式

**本地演示（默认）**：Java 17 + Spring Boot 3.5.15 + Spring Security + MyBatis-Plus 3.5.12 + H2文件数据库。会话保存在应用进程内，通知经持久化事件表由本地调度任务送达，通常约3秒。无需安装 MySQL、Redis 或 RabbitMQ。退出程序后业务数据仍保存在 `data/`，重启后需要重新登录。

**完整组件模式**：MySQL + Redis会话及类别缓存 + RabbitMQ异步通知，启用 `infra` 配置。详见 `docs/完整组件部署.md`。这一模式已提供代码和配置，但当前环境未完成外部服务联调，不能把演示模式的通过结果当作这一模式的验证结果。

## 业务规则

工单主流程：待审核 → 待派单 → 待接单 → 维修中 → 待验收 → 已完成。

- 待审核可以拒绝；待审核或待派单可以由学生取消。
- 待接单可以由宿管重新派单，必须说明原因。
- 学生验收失败可退回维修中，轮次增加，保留既有处理记录。
- 同一用户和请求编号不会生成重复工单；相同请求编号但内容不同会拒绝。
- 修改状态须同时匹配旧状态和版本号，并发派单只允许一个请求成功。
- 工单更新、日志、通知事件在同一事务中提交；事件编号作为通知去重键。
- 默认按角色和数据归属过滤列表、详情、修改和附件下载。管理员不会默认获得全部工单的读取权限。

## 源码与构建

使用 IntelliJ IDEA 打开本目录的 `pom.xml`，选择 Java 17，等待 Maven 下载依赖。运行 `edu.campus.dorm.Application`，默认端口为8080（start.cmd明确使用18080）。

安装 Maven 3.9 后可使用：

```text
mvn test
mvn package
java -jar target/dorm-repair.jar --server.port=18080
```

项目为测试配置了 Mockito 启动代理，以避免某些 Windows 环境不允许测试工具在运行过程中附加到Java进程的问题。

目录说明：

- `src/main/java/edu/campus/dorm`：认证、控制器、业务服务、消息处理及初始化数据。
- `src/main/resources/static`：HTML、CSS、JavaScript页面，无外部CDN依赖。
- `src/main/resources/schema.sql`：数据库表结构，兼容本项目使用的H2 MySQL模式及MySQL语法。
- `src/main/resources/application-infra.yml`：完整组件配置。
- `src/test`：19项集成测试及测试配置。
- `docs`：测试结果、接口说明、截图步骤及与论文方案的差异。
